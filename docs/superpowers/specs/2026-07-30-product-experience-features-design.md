# Good-Badminton 产品体验功能设计

**日期：** 2026-07-30
**范围：** 功能计划 5.6–5.10
**阶段边界：** 本轮完成本地功能实现与自动化验证，不部署生产环境。

## 1. 目标与原则

本轮将现有“上传并等待分析”的演示流程升级为可恢复的复盘产品：用户只选择一个视频即可完成校准和分析，离开小程序后仍能从任务中心继续查看；分析完成后可直接阅读结构化指标、回合时间轴与精彩片段，并通过受控接口导出或分享结果。

设计遵循以下原则：

- 指标、时间轴、精彩片段和报告共用同一份结构化分析结果，避免重复计算导致数值不一致。
- 不伪造算法能力。当前没有可靠击球识别时，攻防往返次数显示为不可用，精彩推荐仅使用可解释且已具备的数据。
- 删除采用软删除，媒体物理清理由后续部署阶段的后台生命周期任务处理。
- 分享令牌带有效期和任务范围，不能暴露服务器绝对路径或绕过任务所有权。
- 兼容已有任务：缺少新增字段或结构化结果的历史任务仍可查看原视频和图表。

## 2. 总体架构与数据流

分析流水线继续产出 `metadata.json`、`detections.jsonl`、标注视频和图表，并新增：

- `analytics.json`：视频摘要、数据质量、整场/球员/逐回合指标、回合边界。
- `highlights.json`：精彩片段范围、推荐评分、推荐原因、用户调整状态。
- `summary.csv`：核心指标与回合摘要的表格导出。
- `report.html`：可打印的完整分析报告，包含视频信息、核心指标、热力图引用、回合摘要和质量说明。

分析完成时一次性生成这些文件，并由任务服务归档至任务结果目录。后端只读取已归档的结构化结果，不在每次请求时扫描整份 JSONL。

## 3. 任务中心

### 3.1 数据模型

`analysis_tasks` 增加：

- `name`：用户可编辑的任务名称。
- `cover_path`：从候选校准帧中选定的封面相对路径。
- `video_metadata_json`：原文件名、大小、时长、宽高、帧率。
- `stage`：上传、校准、排队、分析、结果生成等用户可理解阶段。
- `deleted_at`：软删除时间。
- `source_task_id`：重试或重新分析时追溯来源任务。

状态扩展为 `created`、`uploading`、`queued`、`running`、`publishing`、`succeeded`、`failed`、`cancelled`。取消仅对 `created`、`uploading` 和 `queued` 生效；当前进程内执行器不能安全中止已经运行的 GPU 推理，因此运行中任务明确提示暂不可取消。

### 3.2 列表与操作

任务列表使用基于 `(created_at, id)` 的游标分页，支持状态筛选和稳定向后翻页。默认排除软删除任务。列表卡片显示名称、封面、创建时间、视频时长、状态阶段、进度和失败原因。

恢复动作按状态显示：

- `failed`：重试、重新分析、删除。
- `cancelled`：重新分析、删除。
- `queued`：取消、删除（取消后）。
- `succeeded`：查看结果、重新分析、删除。
- 草稿任务：继续校准、删除。

“失败重试”复制原任务的输入、校准和参数后直接重新入队；“重新分析”复制输入和校准后创建可编辑的新草稿。两者都保留来源任务，不覆盖历史结果。

### 3.3 小程序生命周期

任务中心成为首个标签页，分析创建流程作为独立页面打开。页面 `onHide`/`onUnload` 停止轮询，`onShow` 立即刷新首屏状态；仅当当前列表存在非终态任务时低频轮询。任务 ID 和当前草稿保存在本地，重新进入时以服务端状态为准恢复。

## 4. 上传与校准

用户使用 `wx.chooseMedia` 选择视频后，立即展示文件名、大小、时长、宽高和预计处理时间区间。预计时间是基于视频时长与档位的保守区间，并明确标为估算。

上传前展示固定机位、横屏、完整球场和光照提示。后端接收视频后使用 OpenCV 在视频前段和均匀时间点抽取候选帧，返回受控预览资源；第一张合格候选帧默认作为封面和校准模板，因此普通用户不再额外选择图片。

参数面向普通用户简化为：

- 快速：轻量姿态模型，减少可视化开销。
- 标准：当前默认平衡配置。
- 高精度：性能档姿态模型和完整可视化。

原模型家族、语言、叠加开关和模型路径进入高级设置。

手动校准组件基于原图坐标保存四点，显示层只维护缩放与偏移。支持点击/拖拽角点、双指缩放或按钮缩放、重置以及凸四边形、面积、顺序和边界检查。坐标换算采用统一纯函数并以多种屏幕比例测试，取整误差不超过 1 像素。

## 5. 结构化指标与可信度

`analytics.json` 包含：

- 比赛总时长、有效回合数、平均和最长回合时长。
- 上、下场球员的移动距离、平均速度、最大速度、场区覆盖率。
- 前中后场驻留比例与左右区域分布。
- 整场、单球员、单回合三个统计维度。
- 每个指标的数据来源、单位、可用状态和可信度。

可信度不是模型虚构概率，而由有效坐标比例、轨迹连续率、异常速度过滤比例和回合有效样本数计算。界面同时显示等级和解释，例如“中：有效轨迹覆盖 78%”。

指标计算抽取为无 UI 依赖的纯 Python 模块，分析视频叠加和结构化结果共同调用同一计算逻辑。测试可从固定 JSONL 重新计算并与 `analytics.json` 对比。

## 6. 回合时间轴与精彩片段

回合由当前连续检测帧规则生成，记录开始帧、结束帧、开始秒、结束秒和持续时间。点击时间轴通过 `VideoContext.seek(start_sec)` 跳转，时间使用帧号除以 FPS 计算，并验证误差不超过 1 秒。

精彩片段按持续时间、双方移动距离和速度强度归一化评分。每个推荐项必须带可读原因，例如“本场持续时间前 10%，双方移动强度较高”。攻防往返次数字段在击球识别未启用时为 `null`，并注明暂不可用。

第一版允许用户：

- 取消系统推荐。
- 调整开始和结束时间，但范围不得越过视频边界且开始时间小于结束时间。
- 恢复系统推荐值。
- 保存调整后的精彩片段视频。

片段导出由后端基于已归档视频裁剪，生成任务私有资源。

## 7. 导出与分享

小程序继续支持保存图表和完整结果视频，并增加精彩片段保存。WebUI 增加下载原始 JSONL、摘要 CSV 和完整 HTML 报告。

分享采用随机高熵令牌，数据库只保存令牌哈希、任务 ID、创建者、过期时间和撤销时间。分享接口只暴露允许的报告或片段资源；过期、撤销、软删除任务或不存在的资源均拒绝访问。当前本地阶段生成相对分享路径，不配置生产域名。

## 8. 错误处理与兼容

- 后端返回稳定业务错误码和可执行恢复建议，小程序优先展示建议。
- 历史任务缺少视频元数据时显示“未知”，不阻止查看。
- 历史成功任务没有 `analytics.json` 时仍显示视频和图表，并提示结构化复盘不可用。
- 候选帧抽取失败时保留兼容入口，允许用户手动选择模板图片。
- 报告或片段生成失败不改变主分析任务的成功状态，只标记对应衍生资源失败。

## 9. 测试与验收

后端测试覆盖迁移字段、游标分页、状态筛选、所有权、取消、重试、重新分析、软删除、候选帧、结构化资源、分享过期与撤销。分析模块使用固定 JSONL 覆盖指标复算、区域比例、回合边界、可信度和精彩推荐原因。

小程序测试覆盖任务中心分页/刷新/前后台轮询、单视频流程、档位映射、角点拖拽与坐标误差、仪表盘切换、视频跳转、精彩片段编辑和保存。WebUI 测试覆盖 CSV、JSONL 和报告导出入口。

自动化验证完成后，仍需在微信开发者工具中手动验证媒体选择、双指缩放、视频跳转、相册权限和页面生命周期；本轮不进行上传、审核或生产部署。

3. 实现视频元数据与候选校准帧。
4. 实现任务中心与可恢复分析流程。
5. 实现结果仪表盘、时间轴和精彩片段。
6. 实现导出、分享访问控制和 WebUI 入口。
7. 执行后端、小程序、分析模块测试及静态检查。
