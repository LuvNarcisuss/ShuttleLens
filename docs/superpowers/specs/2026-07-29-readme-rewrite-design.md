# README 重写设计

## 目标

重写仓库根目录 `README.md`，让第一次接触项目的普通使用者能够快速判断项目用途、选择合适的运行入口并完成本地体验，同时准确覆盖 CLI、Gradio WebUI、FastAPI 后端和微信小程序。

README 必须以当前仓库内容为依据，不保留失效链接，不虚构截图、性能结果或尚未完成的能力。

## 目标读者

主要读者是希望使用项目完成羽毛球视频分析的普通用户。开发者和部署维护人员是次要读者，其需要的架构、测试和生产配置放在 README 后半部分。

## 内容结构

README 按以下顺序组织：

1. 项目简介与当前状态
2. 效果与核心能力
3. CLI、WebUI、微信小程序三种使用方式的选择说明
4. 环境要求与快速安装
5. CLI 最短使用流程
6. WebUI 启动与操作流程
7. 微信小程序与 FastAPI 后端的组成、开发启动和生产前置条件
8. 分析输出文件说明
9. 模型选择与性能注意事项
10. 项目目录结构
11. 测试与开发命令
12. 当前限制和已知问题
13. 相关项目、致谢与许可证

## 内容取舍

- 保留能够从代码和配置确认的姿态检测、羽毛球检测、球场映射、轨迹统计、结果视频及图表输出。
- 保留 CLI、WebUI、后端和微信小程序，但避免把四套入口写成彼此独立的项目。
- 删除已经不存在的 `README_EN.md` 链接。
- 删除指向不存在 `assets/` 文件的图片和演示链接，不创建替代图片。
- 压缩更新日志、开发计划和宣传性描述；未实现能力放入“当前限制”。
- 保留同系列项目、上游依赖致谢和 Apache License 2.0 说明。
- 常用 CLI 参数保留少量示例，完整参数交给 `python main.py --help`。

## 安装与运行说明

- Python 最低版本统一写为 3.10，与后端 `pyproject.toml` 一致。
- 根目录 `requirements.txt` 当前使用 CUDA 12.1 的 PyTorch wheel，README 必须明确 NVIDIA/CUDA 依赖，不能继续声称默认安装为 CPU 版本。
- CLI 入口使用 `python main.py --video-path <路径>`。
- WebUI 入口以仓库实际模块和依赖为准，不引用不存在的依赖文件。
- 后端说明 MySQL、Alembic、FastAPI 配置和启动方式。
- 小程序说明开发者工具导入目录、API 地址和微信平台能力前置条件。

## 安全与生产边界

生产说明必须明确区分开发 mock 模式和真实微信环境。README 不提供真实密钥示例，不引导用户把以下信息写入小程序：

- 微信 AppSecret
- 微信 access token
- session_key
- OpenID
- 完整手机号或手机号密文

生产部署还需配置独立 JWT 密钥、手机号加密密钥、HTTPS API 地址，以及微信公众平台 request、uploadFile、downloadFile 合法域名。

## 写作风格

- 使用自然、直接的中文，避免广告式措辞和重复强调。
- 标题和列表用于导航，不使用大量表情符号或机械粗体。
- 命令示例可以复制执行，并明确工作目录。
- 对实验功能、环境限制和管理员验证项如实说明。

## 验证标准

重写完成后进行以下检查：

1. 检查 README 中所有仓库内相对链接和文件路径是否存在。
2. 检查 CLI、WebUI、后端、小程序入口是否与当前代码一致。
3. 运行 CLI 帮助命令，确认文档中的主要参数可解析。
4. 运行后端完整测试。
5. 运行小程序完整测试和 TypeScript 静态检查。
6. 使用 `git diff --check` 检查 Markdown 格式问题。

无法在当前自动化环境完成的微信开发者工具和真机验证必须单独列出，不能标记为已通过。
