# “我的”主页与账号设置改版设计

## 背景与目标

当前“我的”页已经展示头像、昵称、登录状态、最近任务、资料设置和账号安全。本次改版参考用户提供的移动端截图，将资料入口与账号设置从主页内容区移到蓝色个人信息区右上角，主页聚焦“我的分析”和“羽球生涯”。

继续使用微信原生 WXML、WXSS 和 JavaScript，不引入 uni-app 或第三方组件库。品牌保持“羽球拍档”，视觉延续现有明亮蓝白、活力亲和风格。

## 范围

### 包含

- 重构 `pages/profile/index` 的信息层级和数据展示。
- 复用 `pages/profile-edit/index` 作为“个人信息”页面。
- 新增 `pages/account-settings/index` 账号设置页。
- 在 `app.json` 注册账号设置页。
- 从最近一次成功分析结果读取上半场球员数据，生成“羽球生涯”指标。
- 保留最近任务、查看结果、登录入口、加载态、空状态和错误态。

### 不包含

- 不新增密码体系。
- 不实现微信解绑、身份切换或账号注销后端能力。
- 不建立跨场次累计统计，不把单场数据描述为历史累计值。
- 不实现指定球员绑定；第一版固定使用分析结果中的 `players.upper`，为后续选择球员保留清晰的数据入口。
- 不修改分析算法、任务接口、登录协议或后端数据模型。

## 方案选择

采用方案 A：读取最近一次成功任务的分析结果，将 `analytics.players.upper` 作为主页“羽球生涯”数据源。

相比在前端汇总全部历史任务，这一方案不会引入大量请求和错误的加权平均；相比新增后端汇总接口，改动更小，能够先完成用户确认的页面结构。页面必须标注“最近一次分析 · 上半场球员”，避免用户误解为累计生涯数据。

未来支持指定球员时，可将固定的 `upper` 替换为用户账号绑定的球员标识，再演进为服务端汇总接口。

## “我的”主页设计

### 蓝色个人信息区

- 左侧显示头像；没有头像时使用现有“羽”字占位。
- 中部显示昵称、资料状态、脱敏手机号和短账号标识。
- 账号标识来自当前用户的 `id`，仅在主页做适合窄屏的截断；账号设置页显示完整值。
- 右上角放置两个独立的图标按钮，点击区域至少为 `88rpx × 88rpx`：
  - “个人信息”：进入 `/pages/profile-edit/index`。
  - “账号设置”：进入 `/pages/account-settings/index`。
- 两个图标按钮提供明确的无障碍标签；加载中或未登录时按状态隐藏或禁用。
- 未登录用户继续显示“微信快捷登录”，进入现有登录流程。

### 我的分析

- 使用图一“我的约球”的位置和视觉层级，文案改为“我的分析”。
- 点击后通过 `wx.switchTab` 进入 `/pages/tasks/index`。
- 下方最近分析区保留当前任务卡片能力，主页最多展示最近两项。
- 标题使用“最近分析”，右侧提供“查看更多”；点击后进入任务页。
- 已完成任务可以进入结果页，其他状态只展示进度和状态，不增加新的业务操作。

### 羽球生涯

- 标题为“羽球生涯”，副标题固定说明“最近一次分析 · 上半场球员”。
- 默认采用 3×3 指标布局，映射真实的上半场球员字段：
  1. 平均速度：`average_speed_mps`，显示时换算为 km/h。
  2. 最高速度：`maximum_speed_mps`，显示时换算为 km/h。
  3. 移动距离：`distance_m`，单位 m。
  4. 场地覆盖率：`court_coverage_ratio`，显示为百分比。
  5. 前场占比：`zones.front`。
  6. 中场占比：`zones.mid`。
  7. 后场占比：`zones.back`。
  8. 左侧占比：`sides.left`。
  9. 右侧占比：`sides.right`。
- 速度保留一位小数，距离保留一位小数，比率转换为整数百分比。
- 某项缺失或 `available === false` 时显示“—”，不得伪造为 0。
- 点击“查看本场详情”进入这次分析的结果页。
- 没有成功任务时显示“完成一次分析后，这里会生成你的羽球数据”，并提供进入任务页的按钮。
- 最新成功任务没有结构化分析结果时显示“本次结果暂无生涯数据”，最近任务列表仍可正常使用。

## 账号设置页设计

新增原生页面 `pages/account-settings/index`，使用系统导航栏返回能力，标题为“羽球拍档 · 账号设置”。页面采用白底列表和蓝色主操作，危险操作单独使用红色。

### 真实可用项

- 账号 ID：读取 `getCurrentProfile()` 返回的完整 `id`，只读展示并支持长文本换行或截断。
- 手机：展示 `masked_phone`；使用微信原生 `open-type="getPhoneNumber"` 和现有 `bindPhone` 接口完成绑定或更换。
- 微信：展示“已绑定”。当前微信登录是唯一身份来源，不提供解绑操作，以免用户失去登录入口。
- 退出登录：先通过 `wx.showModal` 明确确认；确认后调用现有本地 `logout()`，再切回“我的”页显示未登录状态。

### 暂未开放项

按用户选择的方案 A 保留以下内容，但必须显示“暂未开放”，使用禁用视觉且不绑定伪操作：

- 微信解绑。
- 密码重置；当前账号没有密码体系。
- 切换身份；当前没有多身份模型。
- 账号注销；当前没有后端注销接口，不能以本地清缓存冒充注销。

“账号注销”仍采用危险操作的红色语义，但禁用态要明显，避免误认为可执行。

## 数据流

### 主页加载

1. `onShow` 同时请求当前资料和任务列表，维持现有独立失败处理。
2. 从任务列表中选择最近一项 `status === "succeeded"` 的任务。
3. 仅对该任务调用 `getAnalytics(taskId)`。
4. 从 `analytics.players.upper` 生成固定的九项展示数据。
5. 资料、任务和分析数据分别维护加载与错误状态：生涯数据失败不能清空已经成功加载的个人资料和任务。

避免请求视频、图表或高光资源；主页只需要轻量的结构化分析 JSON。

### 页面跳转

- 个人信息图标：`wx.navigateTo('/pages/profile-edit/index')`。
- 账号设置图标：`wx.navigateTo('/pages/account-settings/index')`。
- 我的分析/查看更多：`wx.switchTab('/pages/tasks/index')`。
- 查看结果/查看本场详情：`wx.navigateTo('/pages/result/index?task_id=...')`。

## 交互与异常处理

- 所有关键点击区域至少 88rpx 高宽，适合触屏操作。
- 加载期间显示局部骨架或明确加载文案，不让登录入口闪现。
- 最近任务加载失败时显示可理解的错误，但仍保留个人资料和设置入口。
- 生涯数据加载失败时只影响“羽球生涯”区域。
- 手机授权取消、拒绝、额度不足和接口错误复用资料编辑页现有的区分文案。
- 退出登录必须确认；暂未开放项不能触发 toast 冒充功能。
- 页面底部使用 `env(safe-area-inset-bottom)`，确保全面屏手势区域可用。

## 验证策略

- 主页运行时测试：验证最近成功任务选择、`players.upper` 指标映射、单位换算、缺失数据占位、错误隔离和四类跳转。
- 账号设置运行时测试：验证资料加载、手机号绑定、更换、授权失败、退出确认和本地会话清理。
- 配置测试：解析 `app.json`，确认账号设置页已注册且页面文件齐全。
- 保留现有页面与服务测试，运行完整 `npm test` 和 `npm run typecheck`。
- 不为纯 WXML/WXSS 外观增加脆弱源码快照测试。
- 微信开发者工具视觉验收覆盖登录/未登录、无任务、无结构化结果、完整数据、窄屏、全面屏和大字号。

## 验收标准

- “我的”页不再显示原来的“资料设置”和“账号安全”卡片。
- 顶部两个按钮分别进入资料编辑和账号设置页。
- “我的分析”“最近分析”“羽球生涯”信息层级与参考图一致，并保持羽球拍档品牌风格。
- 羽球生涯数据来自最近一次成功分析的上半场球员，不出现虚构指标。
- 账号设置中只有真实能力可点击，暂未开放能力状态明确。
- 原有登录、编辑资料、任务列表、查看结果和退出登录行为无回归。
