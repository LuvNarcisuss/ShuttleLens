# “羽球拍档”微信小程序界面换肤设计

## 背景与目标

当前 `wx_app/` 是微信原生小程序，提供登录、视频分析、任务管理、结果查看和个人资料能力。此次改版保留原生 WXML、WXSS、JavaScript 架构及全部现有业务逻辑，将六个在 `app.json` 中注册的页面统一为用户确认的方案 A：明亮蓝白、活力亲和、接近参考截图的白卡片和彩色状态标签风格。

品牌名称统一为“羽球拍档”。改版成功的标准是：六个页面具有一致的品牌与组件语言，现有事件、路由、接口字段和运行状态不受影响，自动化测试及类型检查通过，并可在微信开发者工具中正常预览。

## 范围

### 包含

- `pages/tasks/index`：任务首页。
- `pages/analyze/index`：智能分析四步流程。
- `pages/result/index`：视频、数据看板、高光和图表结果。
- `pages/login/index`：协议、微信登录、手机号绑定和资料完善流程。
- `pages/profile/index`：个人资料、最近任务、编辑资料和退出登录。
- `pages/profile-edit/index`：头像、昵称、手机号及保存反馈。
- `app.json`、`app.wxss` 和底部导航所需的轻量本地图片资源。

### 不包含

- 不新增参考产品中的附近场馆、组队约球、足球生涯、身份切换或账号注销业务。
- 不修改后端接口、鉴权机制、数据库结构或分析算法。
- 不迁移到 uni-app，不引入 Vue、React、TDesign 或其他组件库。
- 不删除未注册在 `app.json` 中的 `pages/home`，也不对其进行无关重构。

## 视觉系统

### 色彩

- 品牌主色：`#1688FF`。
- 深一级交互色：`#0878E7`。
- 成功与进行中：`#12B76A`。
- 危险与失败：`#E5484D`。
- 页面背景：`#F5F7FA`。
- 主文字：`#1D2633`。
- 次文字：`#8C96A5`。
- 分隔线：`#E3E8EF`。

文字与背景保持清晰对比；浅蓝背景不承载低对比度蓝色小字。绿色只表示成功、进行中或安全操作，红色只表示失败、退出或删除等危险语义。

### 排版与空间

使用微信设备默认中文字体栈，以 `PingFang SC` 为主。页面标题、分区标题、正文、辅助文案和标签形成稳定层级。尺寸以 `rpx` 为主，页面水平边距统一为 `24–32rpx`，卡片内部间距为 `24–32rpx`，同组元素间距小于跨组间距。

卡片圆角控制在 `16–24rpx`，按钮圆角约 `12–16rpx`；只为浮于浅灰背景的主要卡片使用克制阴影，列表内部以分隔线或间距划分，避免卡片套卡片。

### 品牌与图标

导航和关键品牌区域显示“羽球拍档”。现有根目录绿色 `LOGO.png` 不直接用于蓝白页面；实现时制作轻量的蓝白羽毛球标识及底部导航普通态、选中态 PNG，并放入小程序包内。图标需要在普通屏和高像素密度设备上保持清晰，不依赖 emoji 渲染。

## 页面设计

### 任务首页

顶部使用明亮蓝色品牌区，展示“开始一场复盘”、辅助说明和“新分析”入口。任务列表沿用现有数据和操作，以白色横向卡片呈现封面、文件名、阶段、时间、进度和状态操作。失败、取消、重试、重新分析和删除能力保持不变；长文件名必须单行截断，失败恢复提示允许多行。

### 智能分析

保留视频选择、分析档位、球场检测校准、开始分析四个步骤。每一步使用白色内容区和蓝色编号建立顺序，主操作使用品牌蓝，次操作使用浅蓝或描边样式。高级设置继续渐进展开；禁用态、自动提取失败、手动四角校准和提交进度必须清晰可辨。

### 分析结果

顶部蓝色标题区显示任务编号和可信度信息。结果视频、数据看板、高光时间轴、分享和图表按照现有顺序保留。指标卡采用两列布局，蓝色用于关键值和选中态，绿色用于成功状态。编辑弹层、下载进度、相册权限恢复及资源错误不能被视觉简化遗漏。

### 登录

使用蓝白羽毛球标识、“欢迎使用羽球拍档”和简短价值说明建立品牌首屏。协议勾选、微信登录、手机号绑定、资料完善和完成状态沿用现有分步逻辑。按钮禁用、授权取消和错误信息需要有明确反馈。

### 个人中心

顶部蓝色资料区呈现头像、昵称、登录状态和脱敏手机号；未登录时显示微信快捷登录入口。最近任务、编辑资料和退出登录按信息分组展示。退出登录是危险操作，不与主要蓝色按钮形成同等视觉优先级。

### 资料编辑

采用参考球员信息页的纵向分区结构：头像选择、昵称、手机号和保存操作。保留 `chooseAvatar`、昵称安全校验和 `getPhoneNumber` 能力。上传、保存或手机号更换期间显示加载态，错误文案位于相关操作附近。

## 代码结构与数据流

公共设计 token 和基础样式写入 `miniprogram/app.wxss`，页面特有布局保留在各页面 WXSS 中。WXML 只为实现已确认的信息层级做必要重排；JS 中的数据请求、`setData`、事件处理、路由和微信开放能力保持原有接口。

数据流不变：页面生命周期或用户事件调用现有 `services/`，服务返回结果后由页面 `setData` 更新视图。视觉状态直接由现有字段派生，例如任务状态、进度、登录状态、加载标记和错误消息，不建立第二套重复状态。

底部导航继续使用微信原生 `tabBar`。更新文字、颜色、背景和本地图标，不引入自定义 tab bar，以降低导航回归风险。

## 边缘状态与可访问性

- 覆盖加载、空列表、未登录、授权取消、接口失败、任务失败、资源不可用和权限拒绝状态。
- 可点击区域满足移动端触控尺寸，不能只依赖颜色表达状态。
- 长文件名、任务编号、错误文案和较大系统字号不能导致关键按钮溢出。
- 动效只用于状态反馈和页面内轻量过渡，不增加持续动画，不影响减少动态效果的用户。
- 蓝、绿、红标签同时提供文字说明，避免色觉差异导致语义丢失。

## 验证策略

1. 运行 `wx_app` 的完整 `npm test`，确认页面逻辑和服务测试无回归。
2. 运行 `npm run typecheck`，确认 JavaScript 检查配置无新增错误。
3. 静态检查 `app.json` 的页面和 tabBar 资源路径、各页面 JSON 严格格式及 WXML 事件处理器对应关系。
4. 在微信开发者工具中编译并人工检查六页的正常、加载、空、错误和禁用状态。
5. 至少使用一个窄屏模拟器和一个常见全面屏尺寸检查安全区域、文本截断、滚动及底部导航。

自动化测试不能替代微信开发者工具和真机验证；若本地缺少开发者工具或无法使用微信开放能力，交付时必须明确标注未验证项。
